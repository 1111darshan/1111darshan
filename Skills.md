Company Technology Skill Matrix

Purpose

This skill defines the technology landscape used by the companies in the
company technology database.

The matrix is designed for:

* Company technology discovery
* Resume-to-company skill matching
* Job requirement matching
* Skill-gap analysis
* Learning recommendations
* Company-specific interview preparation
* Career roadmap generation
* Technology research
* Official documentation discovery

⸻

Data Structure

Field	Description
Sub-Skill	Specific technology, service, tool, or component
Skill	Parent technology/platform
Category	Technology classification
Companies	Companies known to use the sub-skill
Official Website	Official vendor/project website
Official Documentation	Official documentation/reference

Skill Matching Rules

Exact Match

An exact sub-skill match receives the highest confidence.

Example:

Candidate: EC2
Job Requirement: EC2
Result: Exact Match

Parent Skill Match

Knowledge of a parent technology does not automatically mean knowledge of
every sub-skill.

Example:

Candidate: AWS
Job Requirement: EC2
Result: Parent Skill Match
Confidence: Partial

The system must not assume that knowing AWS means knowing EC2.

Related Technology Match

Related technologies can provide transferable knowledge but should not be
treated as exact matches.

Example:

Candidate: GKE
Job Requirement: EKS
Result: Related Kubernetes / Managed Cloud Skill
Confidence: Partial

Company Match

The system can determine which companies use a specific technology.

Example:

Technology: EC2
Companies:
- BornDigital
- Omuni
- HDFC Securities

Skuad must not be returned because AWS/EC2 was not present in the supplied
Skuad technology data.

Learning Resource Rules

For every missing skill:

1. Prefer the official technology website.
2. Prefer official documentation.
3. Prefer official tutorials when available.
4. Do not use unofficial resources as the primary documentation source.
5. Preserve the official documentation URL in the skill record.
6. If an official documentation URL cannot be verified, mark it as requiring
    verification instead of inventing a URL.

⸻

Data Integrity Rules

* Do not add a company unless the supplied source data identifies that
    company as using the technology.
* Do not infer company technology usage from job advertisements unless that
    information is explicitly added as a separate source.
* Normalize spelling variations before matching.
* Keep the original company association.
* Keep technology and sub-skill relationships.
* Keep official website and documentation separately.
* Do not replace ambiguous technologies with guessed technologies.
* Mark ambiguous technologies for verification.
* A parent skill does not automatically imply every sub-skill.
* Related technologies should receive partial rather than exact matching.
* Official vendor/project documentation is preferred for learning resources.

⸻

Source Confidence

Each technology relationship can optionally contain a source confidence:

Confidence	Meaning
Confirmed	Explicitly supplied in the company technology matrix
Verified	Confirmed using an additional reliable source
Inferred	Derived from another technology and requires validation
Unknown	Technology was supplied but its exact meaning is unclear

The current company matrix should treat the technologies supplied by the user
as Confirmed company-technology relationships.
